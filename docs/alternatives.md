## 三条不同的技术选择

### ① 局部渐变：我们测到它变差

**他们的做法**：在较大色块内拟合渐变，减少色带。
**我们的做法**：每个多边形一个纯色，不输出渐变。

**实测**：对每层做 PCA 算光照方向、输出 `linear-gradient` 之后，
MAE 从 **11.03 涨到 18.65**。

推测原因（**推测，未单独验证**）：小色块内部本来颜色就均匀，
强行套渐变等于把「量化误差」换成了「渐变拟合误差」，
后者的空间频率和参考图对不上。

⚠️ 这个结论**只在这张图、这套参数下量过**。换一张色块更大的图，
渐变可能确实更好。所以这不是「渐变是错的」，是「我们这张图上量到变差」。

---

### ② 孔洞：桥接 vs 深度排序

**他们的做法**：偶奇填充（`polygon(evenodd, ...)`）+ 用一条「往返桥」连接内外环。
**我们的做法**：按深度排序，让更深的层盖住 —— 不算桥。

| | 桥接 | 深度排序（采用） |
|---|---|---|
| 单个多边形能否自挖洞 | ✅ 可以 | ❌ 不能 |
| 要不要算桥 | 要，几百个嵌套环挨个算 | 不要 |
| 层数 | 少 | 多 |
| 出错风险 | 桥的位置算错会露缝隙 | 洞的位置上必须有更深的层 |

我们选后者的唯一理由是**实现成本**：这个项目里嵌套环太多，
程序化生成桥的代价超过了层数增加的代价。

---

### ③ 残差补偿层：我们没有在别人的实现里看到对应物

**我们的做法**（跑三轮）：

```
第一遍量化 → 渲染 → 和参考图比 → 取误差最大的 N% 像素
  → 对这些像素再跑一次 K-means → 提轮廓 → 追加为更深一层
  → 重复
```

**为什么必需**：嘴巴在参考图里是一个**填充色块**，面积太小，
K-means 拿不到独立色簇，被并进邻近的肤色。局部中值法也检测不到
（它是实心块，不是边缘）。

跑三轮之后，**嘴巴、眼高光、蕾丝孔洞、宝石反光**全部被自动找回 ——
不需要人工指定「这里画嘴巴」，它只是最小化 MAE。

## 其他差异

| 维度 | image-to-css-art | 本仓库 |
|---|---|---|
| 颜色量化 | Oklab 感知空间 + 中位切分 | K-means（RGB） |
| 精度预设 | preview / balanced / faithful | 手动调 K / SIGMA / DENS / TOL |
| 体积预算 | `--max-output-mb` + `--fit` 自动降档 | 无（手动） |
| MAE 自评 | `--score` 内置 | 独立脚本 `measure/remeasure_mae.py` |
| Agent 集成 | 有（Codex 插件 + Skill） | 无 |
| 输出约束检查 | 有（拒绝 script / img / url） | 无 |

**如果要复现这个项目的成果，先试 `image-to-css-art`** ——
它的工程完成度更高，装完就能用。

**如果你想知道「为什么某些参数在这个方向上会变差」**，这个仓库
的 `docs/failures.md` 是那些记录的归档。
