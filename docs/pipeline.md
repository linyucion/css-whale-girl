## 0. 参考图

**输入**：864×1152 的线稿（不是 143×198 的原精灵图）。

那 143×198 放大只会得到糊色块。后来用图生图重绘成 864×1152 ——
**这是「重新画了一遍」，不是插值放大**，所以扇贝蕾丝、鲸鱼绣样、
金色蝴蝶结、发丝分缕这些结构都还在。

裁掉留白之后是 **743×1095**。测量时页面也设成这个尺寸，1:1 比。

## 1. 颜色量化（`src/trace.py`）

```
K = 72              # 聚类数
MiniBatchKMeans     # n_init=10, batch_size=8192, max_iter=600
只在前景像素上跑     # 背景先抠掉，不参与聚类
```

**为什么不是 K 越大越好**：扫过 K = 48 / 72 / 96 / 128，
记下的数字是 14.43 / 5.13 / 14.56 / …，明显不单调 ——
那批数字是噪声，见 `failures.md` 第七节。

最后 K=72 是重新用可信测法量过之后定的。

**中值滤波**：聚类标签做 3×3 中值滤波去锯齿，然后再提轮廓。

---

## 2. 轮廓提取（`src/trace.py`）

对每个颜色区域：

```
1. 建一个 (H+2, W+2) 的浮点蒙版（外面垫一圈 0）
2. skimage.measure.find_contours(pad, 0.5)   ← 0.5 = 亚像素等值线
3. 坐标平移回 (-1, -1)
4. 剔除 < 8 个点的碎片
5. 闭合环去掉重复的最后一个点
```

**为什么垫一圈**：不垫的话，贴着画面边缘的区域轮廓会被裁断。

**为什么是 0.5**：marching squares 在 0.5 等值线处给出的位置，
正好是「覆盖率为一半」的边界。

---

## 3. 平滑与重采样

```
SIGMA = 0.9    # 周期高斯平滑
DENS  = 密度   # 弧长重采样密度
```

顺序是**先按弧长重采样，再沿 x/y 分别做周期高斯平滑**。

**为什么要重采样**：原始轮廓点密度不均匀（marching squares 在
斜边处点更密）。不重采样的话，平滑会变成「在点密的地方弱、
点疏的地方强」。

**为什么是周期**：环是闭合的，首尾要连续，不能用普通卷积
（两端会被拉向 0）。

## 4. 简化（Douglas-Peucker）

```
TOL = 0.9   # 像素容差
```

`skimage.measure.approximate_polygon(pts, tolerance=TOL)`。

**这一步是体积和精度之间最直接的旋钮。** 从 232,517 个顶点
简化到 47,020 个（降 80%）时，gzip 后的 HTML 从 1,055 KB 降到 301 KB。

⚠️ **但简化后的 MAE 没有做过浏览器回归。** 9.69 这个数字对应的是
未简化的版本。要改 TOL，必须重跑 `measure/remeasure_mae.py`。

---

## 5. 深度排序（painter's algorithm）

```
每个区域的深度 = 「有多少个面积更大的区域包含了它的第一个点」
按 (depth, -area) 排序：先画浅的，同深度里先画大的
```

**洞就是这么形成的** —— 洞的位置上有更深的层，画上去就盖住了。
不用算桥，见 `failures.md` 第五节。

判断「包含」用射线法（point-in-polygon）。

---

## 6. 描边层（`src/inkfix.py`，可选）

原图的 lineart 在量化时会丢。单独提一层补回来：

```
描边 mask = (亮度 < 局部中值 × 0.8) 且 (局部差 > 8) 且 (饱和度 < 0.62)
```

三步：

1. 提描边 mask
2. **先 inpaint 掉描边，再对主体做颜色量化** —— 否则描边会把
   邻近的色块拉脏
3. 描边作为最高层，用统一的深中性色绘制

**这一步把 MAE 从 14.4 降到 11.0**，是所有单步里最大的降幅之一。

---

## 7. 残差补偿（`src/residual.py`，可选，跑三轮）

```
每一轮：
  1. 渲染当前所有层，和参考图逐像素比
  2. 取误差最大的像素（连通域面积 >= MINPIX）
  3. 对这些像素的颜色再跑一次 K-means（K2）
  4. 提轮廓、平滑 → 追加为 depth = 当前最大深度 + 1 的层
  5. 重复三轮
```

**为什么会自动找回嘴巴**：它不认语义，只最小化 MAE。
嘴巴那块区域误差大，所以它被补；补的方式恰好是「再画一个色块」。

见 `failures.md` 第六节。

## 8. 输出（`src/build_site.py`）

```
每个多边形：
  .r{i}{background:#rrggbb;clip-path:polygon(x% y%, ...)}
  <b class="r{i}"></b>

坐标：x / W × 100，保留 3 位小数，带 % 号
```

**为什么用 `<b>`**：它是唯一的「默认无样式、可无限嵌套、语义为空」的标签。
`<i>` 和 `<span>` 也都可以，`<b>` 只是最省字节的单字母标签之一。

**为什么坐标用百分比**：可以任意缩放，且父容器换尺寸时不用重算。

## 9. 验证（`measure/remeasure_mae.py`）

```
页面 743×1095 → 打开 → 截图 → 和参考图逐像素比
```

三个口径：

| 口径 | 值 |
|---|---|
| 前景整体 MAE | 12.00 |
| 色块内部 MAE（离边缘 2 像素以上） | 4.49 |
| 边缘带 MAE | 46.95 |

**误差最大的 1% 像素里，有 68.5% 落在边缘带上。**

所以剩下的差距在**边缘的表现方式**，不在采样精度 —— 这也解释了
为什么把 DPR 提到 6 倍只让 MAE 动了 2.2%。
